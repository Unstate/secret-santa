# Архитектура фронтенда

FSD (Feature-Sliced Design). Фичи разрозненные, проект делают два разработчика —
структура обязана позволять делать свои фичи и не мешать друг другу: фичи
изолированы, общее живёт в `shared`, пересечения только через публичные
`index.ts` слоёв.

## Слои и ограничения импортов

| Слой | Что лежит |
|---|---|
| `app` | ядро сайта: вход (`main.tsx`), глобальные стили, конфигурация роутера |
| `features` | функциональный слой: все функции, каждая не зависит от другой |
| `widgets` | скомпонованные UI-компоненты (из фич и shared) |
| `pages` | страницы: композиция виджетов и фич для маршрута |
| `shared` | переиспользуемое: `ui` (компоненты), `api` (запросы), `hooks` (кастомные хуки), `lib` (утилиты) |

Импорты снизу вверх: `shared` могут импортировать все, `app` — никто.
Запрещены импорты между соседями одного уровня: фича не импортирует фичу,
страница — страницу (пересечение фич = через общий `shared` или композицию
на странице/виджете).

## Папки

```
frontend/src/
  app/
    core/          main.tsx — вход приложения
    router/        конфигурация роутера (Router.tsx)
    styles/        глобальные стили: reset, theme (токены), variables, mixins
  features/        одна функция = одна папка (форма, сценарий)
    create-room/      форма «создать комнату» (бюджет в рублях → копейки)
    join-room/        форма «войти по коду» с главной
    player-profile/   имя + аватар игрока, localStorage (общая для форм главной)
    room-join/        вход по ссылке-приглашению на странице комнаты
    room-settings/    настройки комнаты (орг)
    room-exclusions/  пары «не дарит →» (орг, только в лобби)
    room-shuffle/     шафл/ресафл (орг); 409 reshuffle_blocked → текст в карточке
    my-assignment/    «кому я дарю» + вишлист получателя (после шафла, все)
    assignments-order/ порядок пар (орг, после шафла; закрывает ресафл —
                       подтверждение в два клика)
    wishlist/         «мой вишлист»: добавление через парсер WB/Ozon или
                      вручную, правка/удаление своих
  widgets/         пока не используется (папки нет) — композиция живёт на страницах
  pages/
    homepage/        главная: создать/войти
    room/            комната: лобби и после шафла, живая по WS
    dev/             витрина UI-кита (/dev/ui, только в dev)
    not-found/
  shared/
    api/           ApiClient (класс с DI), api.ts (инстанс), base.ts (база URL),
                   ws.ts (RoomSocket), session.ts (токены комнат), errorText.ts
                   (тексты ошибок по code), types.ts (DTO и коды ошибок)
    hooks/         useGet / usePost / usePatch / usePut (путь фиксируется на
                   хуке), useRoomEvents (WS комнаты), request.ts (toApiError)
    lib/           утилиты без React (деньги, валидация, cx)
    ui/            компоненты: каждый в своей папке <Name>/, иконки в ui/icons
```

## Соглашения

- **Индекс-файл.** `index.ts` есть только у разделов — `features`, `pages`,
  `shared/ui`, `shared/api`, `shared/lib`, `shared/hooks`: он собирает их
  публичное. Внутри раздела импорты идут напрямую в файл:
  `import { Button } from '@/shared/ui'`, но
  `import { Spinner } from '../Spinner/Spinner'`.
- **Компонент.** `shared/ui/<Name>/` — `Name.tsx` + `Name.module.scss`,
  без `index.ts`. Страница — `pages/<page>/<PageName>.tsx` + `.module.scss`.
- **Стили.** SCSS-модули рядом с компонентом; цвета/радиусы/тени — только
  токены из `app/styles/theme.scss` (светлая и тёмная темы через
  `[data-theme]`), никаких хардкод-цветов.
- **Комментарии.** Только там, где без них не понять код; никаких описаний
  очевидного.
- **Сессия.** Токен игрока в localStorage (`santa-sessions`: код комнаты →
  токен, можно состоять в нескольких комнатах). Чтение токена внутри
  `shared/api`: HTTP — api.ts достаёт код из пути `/rooms/{code}/…`,
  WS — токен передаётся явно. IndexedDB не используется (решено).
- **Хуки запросов.** Путь фиксируется при создании хука — для запросов с
  динамическим путём (per-item PATCH/DELETE вишлиста) дёргают `api` напрямую.

## Запросы и ошибки

- Экземпляр `api` один на приложение. Токен комнаты вешается по пути
  запроса; для путей без кода комнаты (`/tools/parse-product`) заголовок
  передаётся явно — у `post/patch/put` есть параметр `headers`.
- Ошибки бекенда — единый `{code, message}`. Текст для тостов — через
  `apiErrorText(error)`: для `shuffle_impossible` и `validation_failed`
  берём message (там живые детали), для остальных кодов — стабильные
  тексты из карты (не зависим от формулировок бекенда).

## WebSocket

Живые обновления комнаты — `shared/hooks/useRoomEvents` (над
`shared/api/ws.ts`). Соединение одно на страницу комнаты, отключается по
`null`-коду/токену. События — только триггеры перечитать `GET /rooms/{code}`:
истина в REST, никаких инкрементальных обновлений из событий. Автареконнект
с backoff (1с→15с), после реконнекта — перечитывание; мгновенный ретрай по
`online` и возврату видимости вкладки.
